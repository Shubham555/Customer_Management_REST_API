# Session 8: Complete Request to Response Flow

```
Client -> API endpoint -> Validation -> Business logic -> Database (if required) -> Response
```

## POST /customers

1. Request received: FastAPI receives the HTTP request at `/customers`.
2. Validation: Pydantic checks that `name`, `age` and `city` exist and have the right types.
3. Processing: the endpoint receives validated data and prepares a database record.
4. Database operation: SQLAlchemy inserts the customer into MySQL and commits.
5. Response: FastAPI returns the saved customer, including the generated ID.

```json
{
  "id": 1,
  "name": "Rahul",
  "age": 25,
  "city": "Pune"
}
```

The ID is generated by the database.

## Invalid request

If `age` is `"twenty-five"` and the model expects `int`, FastAPI returns `422 Unprocessable Entity` before the endpoint's main processing runs. Invalid input is rejected before it reaches the database.

## GET /customers

1. Client requests the list.
2. FastAPI calls the GET endpoint.
3. SQLAlchemy queries MySQL.
4. MySQL returns matching records.
5. FastAPI converts the records to JSON.
